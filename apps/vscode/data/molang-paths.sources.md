# Where the Molang path catalogue comes from

Generated by `apps/vscode/tools/build-molang-paths.mjs` next to `molang-paths.json`. Every path in the
catalogue is listed here with the public source(s) it was derived from:

- **BC**: derived from the Blockception schemas (github.com/Blockception/Minecraft-bedrock-json-schemas, as
  bundled in the Blockception VS Code extension): nodes with `"format": "molang"` or a title starting "Molang".
  **BC (description)**: a string-typed Blockception node with no marker whose description calls it Molang
  ("A Molang expression defining ...").
- **MJ**: derived from Mojang's published JSON schemas (github.com/Mojang/bedrock-samples, `metadata/json_schemas`):
  nodes referencing `Expression Node.json`, `Molang string.json` or `Molang Expression.json`. The versions listed
  are the schema directories that mark the path.
- **curated**: `molang-paths.overrides.json`, checked against the vanilla files in bedrock-samples by
  `apps/vscode/tools/check-molang-paths.mjs`. Each curated entry carries its reason in the overrides file.

Inputs of this build: Blockception schemas present, Mojang schemas present; 670 Blockception and 131 Mojang schema hits.

## File types without Molang

Checked and left out of the catalogue: neither schema set marks a Molang field in them and the golden check
finds no Molang-looking string in their vanilla files.

- minecraft:spawn_rules: conditions are filters and fixed-value components; no schema marks Molang, none in the 60 vanilla files
- loot tables (root key pools): functions and conditions take fixed values and ranges
- trade tables (root key tiers): fixed values and ranges
- minecraft:camera_preset: no schema marks Molang; not present in bedrock-samples
- minecraft:fog_settings: fixed values
- minecraft:client_biome: fixed values
- minecraft:atmosphere_settings, minecraft:lighting_settings, minecraft:color_grading_settings, minecraft:water_settings: keyframed fixed values (object keys are times, not Molang)
- minecraft:block_culling_rules, minecraft:dimension, minecraft:voxel_shape: fixed values
- recipes, item catalog, texture sets, flipbook/terrain/item texture lists, sound_definitions, music_definitions, UI: fixed values or resource names
- minecraft:jigsaw, minecraft:structure_set, minecraft:template_pool: fixed values; the block predicates of processor lists do carry tag filters and are catalogued

## Hand-curated entries and their reasons

- added minecraft:client_entity `description/render_controllers/[*]/*`: Render-controller conditions ({"controller.render.x": "query.is_powered"}); no Blockception marker. Many vanilla client entities.
- added minecraft:client_entity, minecraft:attachable `description/scripts/variables/*` (key): Keys of scripts.variables are the variables being declared public; the values ("public") are not Molang.
- added minecraft:client_entity `description/scripts/scaleX`, `description/scripts/scaleY`, `description/scripts/scaleZ`: Spelled with a capital axis letter in the vanilla magma cube; the schemas only list scalex/scaley/scalez.
- added minecraft:client_entity `description/scripts/initialize/[*]`, `description/scripts/pre_animation/[*]`: The game joins the array into one program: vanilla husk/zombie/piglin pre_animation opens a block in one element ("(v.melee_spear_equipped) ? {") and closes it several elements later ("};").
- added minecraft:attachable `description/scripts/initialize/[*]`, `description/scripts/pre_animation/[*]`: Same scripts block as the client entity: statements, joined into one program.
- added minecraft:attachable `description/scripts/animate/[*]/*`: Same scripts block as the client entity (vanilla bow: "wield_first_person_pull": "query.main_hand_item_use_duration > 0.0f && c.is_first_person"); Blockception's attachable schema lacks it.
- added minecraft:attachable `description/scripts/scalex`, `description/scripts/scaley`, `description/scripts/scalez`: Same scripts block as the client entity.
- added minecraft:attachable `description/scripts/should_update_bones_and_effects_offscreen`, `description/scripts/should_update_effects_offscreen`: Same scripts block as the client entity.
- added minecraft:attachable `description/render_controllers/[*]/*`: Same render-controller condition form as the client entity.
- added minecraft:attachable `description/item/*`: Keys are item identifiers, values the condition under which this attachable applies (vanilla armour: "query.owner_identifier == 'minecraft:player'").
- added render_controllers `*/materials/[*]/*`: Keys are bone-name globs, values pick the material ("variable.is_enchanted ? Material.enchanted : Material.default", "Array.materials[query.is_invisible]"); no Blockception marker.
- added render_controllers `*/part_visibility/[*]/*`: Keys are bone-name globs, values the visibility condition; the most common Molang field no schema marks (about 200 vanilla instances).
- added render_controllers `*/arrays/textures/*/[*]`, `*/arrays/materials/*/[*]`, `*/arrays/geometries/*/[*]`: Array elements are resource references (Texture.x, Material.x, Geometry.x) that the geometry/materials/textures expressions index into.
- added render_controllers `*/arrays/textures/*`, `*/arrays/materials/*`, `*/arrays/geometries/*` (key): Keys declare the Array.x names the expressions refer to.
- added animations `*/bones/*/rotation/[*]/x`, `*/bones/*/rotation/[*]/y`, `*/bones/*/rotation/[*]/z`: Legacy per-axis rotation list, [{"y": "180.0 - this"}, {"x": "query.body_x_rotation"}], used by the vanilla squid; not in any schema.
- added minecraft:entity `description/scripts/animate/[*]/*`: BP entity animate conditions; Blockception types them as plain strings.
- added minecraft:entity `events/**/set_property/*`: set_property values are Molang for int/float/bool properties (vanilla creaking: "math.clamp(query.property('minecraft:creaking_swaying_ticks') + 1, 0, 6)"); for enum properties a plain value. Reached through nested sequence/randomize, hence **.
- added minecraft:entity `@components/minecraft:ambient_sound_interval/event_names/[*]/condition`: Condition choosing the ambient sound (vanilla allay: "query.is_using_item"); Blockception types it as a plain string.
- added minecraft:entity `@components/minecraft:rideable/seats/lock_rider_rotation`, `@components/minecraft:rideable/seats/[*]/lock_rider_rotation`: Documented by Mojang as a number or Molang expression, like rotate_rider_by next to it.
- added particle_effect `curves/*` (key): Curve names are the variables the curve is read through ("variable.shrink").
- added particle_effect `events/*/**/expression`, `events/*/**/pre_effect_expression`: Event nodes nest through sequence/randomize to any depth; Mojang's schema is recursive there, so the walk sees one level only.
- added entity_sounds `entities/*/variants/key`: Sound-variant selector in sounds.json, evaluated on the entity and returning the variant name ("query.is_baby ? 'baby' : query.property('minecraft:sound_variant')"); no schema marks it.
- added minecraft:conditional_list `conditional_features/[*]/condition`: Condition choosing a feature, documented by Mojang as Molang; no Blockception marker.
- patched minecraft:client_entity, minecraft:attachable `description/scripts/parent_setup`: Statements run on the parent before it renders (they set variables); Blockception titles it Molang Number.
- patched minecraft:entity `description/properties/*/default`: An enum property's default is a plain value ("unrolled", "default"); int/float/bool defaults may be Molang.

- patched animations `*/particle_effects/*/pre_effect_script`, `*/particle_effects/*/[*]/pre_effect_script`: Runs statements on the spawned effect (sets its variables); not an animation value.
- removed minecraft:client_entity `description/scripts/variables/*`: The values are access modifiers ("public"); the keys are the Molang names (added as target key).
- removed particle_effect `components/minecraft:emitter_lifetime_events/timeline/*`: Timeline values are event names, not Molang (a description mentions Molang).

## Molang-looking strings that are not Molang

Places in the vanilla files where a string contains something like `query.x` or `v.x` but the field is not
evaluated as Molang. The golden check accepts these without a catalogue entry.

- minecraft:client_entity `description/geometry/*`: Geometry identifiers ("geometry.agent") bound to short names that render controllers reach as Geometry.<short name>. The dotted form looks like the geometry. namespace but is a resource id.
- minecraft:attachable `description/geometry/*`: Geometry identifiers, as for the client entity.
- minecraft:geometry `[*]/description/identifier`: The geometry's own identifier ("geometry.allay").
